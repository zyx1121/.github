# Contributing

Thanks for stopping by. These rules apply to every `zyx1121` repo unless that repo says otherwise.

## Before you start

- Bug or small fix: open a PR directly.
- New feature or breaking change: open an issue first, so we agree on the shape before you build it.

## Pull request flow

1. Fork and branch from `main`.
2. Keep the change scoped: one topic per PR.
3. Make sure CI is green and the README still tells the truth.
4. PRs are squash-merged, so the PR title becomes the commit message. Write it like one.

## Style

- Versions follow [SemVer](https://semver.org); API and protocol schemas use `vN`.
- Match the surrounding code and structure. Consistency beats personal taste.
